# 🛰️ Грант-радар: моніторинг грантів для комунальних і приватних підприємств

AI-агент, який **цілодобово моніторить грантові можливості та програми допомоги в ЄС і Україні**,
відбирає релевантні, **розділяє їх на «для комунальних» і «для приватних» підприємств** і
готує чернетки заявок, автоматично підставляючи дані вашої організації.

> **Працює виключно на безкоштовних API.** Жодної платної підписки: дані беруться з
> відкритих API ЄС і донорів (без ключів), AI-шар — з безкоштовних tier-ів Groq / Gemini /
> OpenRouter, автозапуск — GitHub Actions, хостинг — GitHub Pages.
> Повний каталог: **[docs/FREE-APIS.md](docs/FREE-APIS.md)**.

## Що робить агент

| Крок | Що відбувається |
|---|---|
| 1. Збір | 13 джерел: офіційні API ЄС (гранти + тендери), МФО, українські донори та міністерства |
| 2. Нормалізація | Єдина структура: назва, програма, статус, **дедлайн**, бюджет, посилання. Дедлайни витягуються навіть із тексту новин («до 15 листопада 2026», «deadline 30 November 2026») |
| 3. Скоринг | Бал 0–100 за профілем: тематика, гео-відповідність, ознаки конкурсу, мінус-слова, терміновість |
| 4. **Класифікація заявника** | 🏛 комунальні / ОМС · 🏭 приватний бізнес · 🤝 обидва · ❔ уточнити |
| 5. AI-аналіз *(безкоштовний ключ)* | Резюме українською, перевірка прийнятності, наступні кроки |
| 6. Виведення | Дашборд з групуванням за типом заявника, статичний сайт, JSON API, Markdown-дайджест, Telegram |
| 7. **Чернетка заявки** | Агент бере досьє з `config/memory.yaml` і сам заповнює адмінчастину, бюджет, чеклісти, а з LLM — і змістовні розділи |

Зараз у базі після першого запуску: **~1040 можливостей**, з них для комунальних — 389,
для приватних — 542 (решта потребує уточнення типу заявника).

## Поділ «комунальні / приватні»

Кожна можливість класифікується за текстом умов (`src/grant_radar/classify.py`):

- 🏛 **communal** — municipality, local authority, public body, комунальне, громада, ОМС
- 🏭 **private** — SME, business, entrepreneur, МСП, ФОП, підприємці, стартап
- 🤝 **both** — «legal entities», консорціуми, public-private, обидва набори ознак
- ❔ **unknown** — прямих вказівок немає, потрібна перевірка людиною

Де видно поділ:
- **дашборд** — окремі секції з лічильниками + фільтр «тип заявника»;
- **статичний сайт** на GitHub Pages — те саме, працює без сервера;
- **дайджест** (Markdown / Telegram) — окремі розділи для кожного типу;
- **CLI**: `python -m grant_radar top --benef communal` / `--benef private`;
- **API**: `/api/opportunities?beneficiary=private`.

З LLM-ключем класифікація додатково уточнюється моделлю.

## Файл-пам'ять: `config/memory.yaml`

Розширене досьє організацій, з якого агент заповнює заявки. Підтримує **кілька організацій
одночасно** (наприклад, КП і приватне ТОВ) — агент сам обирає потрібну за типом гранту.

Що в ньому:

| Секція | Для чого в заявці |
|---|---|
| `identity` | назви UA/EN, ЄДРПОУ, КВЕД, засновник, форма власності |
| `contacts` | юридична адреса UA/EN, керівник, контактна особа проєкту, бухгалтер |
| `international_ids` | **PIC** порталу ЄС, LEI, UEI, UNGM — без них заявку в ЄС не подати |
| `banking` | IBAN UAH/EUR/USD, SWIFT, кореспондентський банк |
| `staff` | чисельність, ключові фахівці, англомовні працівники |
| `finance` | обороти за 3 роки, аудит, **спроможність співфінансування** |
| `assets` / `permits` | техніка, полігон, ділянки, ліцензія на поводження з відходами |
| `operations` | населення, тонни ТПВ/рік, % сортування, ключові проблеми |
| `experience` | попередні проєкти, донори, партнери, місто-побратим |
| `strategy` | стратегія громади, план управління відходами, SECAP, SDG |
| `project_pipeline` | готові ідеї проєктів — агент підбирає їх під конкурси |
| `boilerplate` | стандартні тексти UA/EN: опис, місія, гендерна політика, сталість |
| `documents` | де лежать статут, витяг з ЄДР, фінзвітність |
| `sme_status` *(для приватних)* | категорія МСП за ЄС, працівники, оборот, de minimis, UBO |

Перевірка заповненості:

```bash
python -m grant_radar memory
```

```
▌ kp (communal, активна) — заповнено 15% (26/178 полів)
    contacts             █·········  17%
    finance              ··········   6%
    ⚠️  критичні незаповнені поля: identity.edrpou, banking.iban_uah, …
```

> ⚠️ Файл містить персональні та банківські дані. Тримайте репозиторій **приватним**
> або додайте `config/memory.yaml` у `.gitignore` (заготовка вже є в кінці файлу).

## Чернетка заявки

```bash
python -m grant_radar draft --benef communal          # для найкращої можливості для КП
python -m grant_radar draft --uid <id> --org private  # конкретна можливість і організація
```

У `data/drafts/<id>-<назва>.md` з'явиться документ:

0. **Паспорт можливості** — донор, програма, дедлайн, бал, тип заявника, посилання
1. **Адміністративні дані** — 22+ поля заявки, заповнені з пам'яті; незаповнені позначені ⚠️
2. **Проєктна ідея** — найкращий збіг із вашого `project_pipeline`
3. **Змістовна частина** — з LLM: проблема, мета, заходи, результати з індикаторами,
   цільові групи, сталість, відповідність політикам ЄС, project summary (EN), ризики
4. **Бюджет** — скелет таблиці з вашою спроможністю співфінансування
5. **Пакет документів** — чеклист зі статусом кожного файлу
6. **Чекліст перед подачею**
7. **Що терміново додати в memory.yaml**

Те саме через API: `GET /api/draft/<uid>` (кнопка «📝 чернетка заявки» на кожній картці).

## Швидкий старт

```bash
pip install -r requirements.txt
export PYTHONPATH=src

python -m grant_radar sources                  # перелік джерел
python -m grant_radar collect                  # сканування + скоринг + класифікація
python -m grant_radar top -n 15 --benef communal
python -m grant_radar memory                   # заповненість досьє
python -m grant_radar draft --benef communal   # чернетка заявки
python -m grant_radar serve                    # дашборд на http://localhost:8000
```

Решта команд: `rescore` (перерахунок після правок профілю, без мережі),
`export` (статичний сайт у `docs/`), `digest --min-score 45` (Markdown + Telegram),
будь-яка команда з `--no-llm` — примусово без AI.

## Безкоштовний AI-шар

Досить **одного** ключа з безкоштовним tier. Агент сам визначає провайдера за змінними
оточення у такому порядку:

| Провайдер | Змінна | Де взяти безкоштовно |
|---|---|---|
| Groq *(рекомендовано)* | `GROQ_API_KEY` | https://console.groq.com/keys |
| Google Gemini | `GEMINI_API_KEY` | https://aistudio.google.com/apikey |
| OpenRouter (моделі `:free`) | `OPENROUTER_API_KEY` | https://openrouter.ai/keys |
| Cerebras | `CEREBRAS_API_KEY` | https://cloud.cerebras.ai/ |
| Mistral | `MISTRAL_API_KEY` | https://console.mistral.ai/ |
| Ollama (локально) | `OLLAMA_BASE_URL` | https://ollama.com/ |

Без жодного ключа агент повністю працездатний — просто без AI-резюме та без
згенерованої змістовної частини заявки.

За запуск LLM аналізує щонайбільше `llm_max_items` (типово 25) **нових** записів і ніколи
не аналізує той самий двічі, тому безкоштовних лімітів вистачає з запасом.

## Налаштування профілю (`config/profile.yaml`)

Тематичні групи та їхні бали: `waste` 30, `municipal` 25, `business` 22, `urban` 18,
`transport` 18, `recovery` 15, `cross_border` 12, `energy` 12, `water` 10.
Для водоканалу — підніміть `water`; для суто бізнесового моніторингу — `business`.

```
бал = (Σ балів тем × 1.0 за збіг у заголовку / 0.55 за збіг у тексті
       + гео + ознаки фінансування − мінус-слова
       + бонус за дедлайн ≤ 45 днів + бонус за відкритий конкурс)
      × вага джерела × scale
```

Запобіжник: якщо профільного слова немає **в заголовку**, запис не отримає «🔥 висока» —
так відсіюються оборонні та суто наукові конкурси ЄС, у тексті яких згадуються «cities»
і «Ukraine». З LLM підсумковий бал = 60 % правила + 40 % оцінка AI.

## Обмеження

- SEDIA і TED — публічні, але неофіційні API: якщо Комісія змінить формат, збирач треба
  оновити (по одному файлу на джерело).
- Частина українських сайтів (Мінрозвитку, ГУРТ, Дія.Бізнес) не має RSS або закрита
  Cloudflare — для них потрібен HTML-збирач.
- Класифікація заявника за ключовими словами дає ~85 % точності: **завжди перевіряйте
  умови прийнятності в офіційному документі конкурсу** перед подачею.
- Агент знаходить, ранжує і готує чернетки, але **не подає заявки** — фінальне рішення
  і підпис за людиною.

Напрям визначається групами ключових слів із `config/profile.yaml` (22 групи).
Щоб додати власний напрям: додайте групу в `keyword_groups`, впишіть її ключ у
`TRACK_ORDER`, `LABEL`, `SHORT` у `src/grant_radar/tracks.py` і, якщо тема профільна,
у `CORE_GROUPS` у `src/grant_radar/scoring.py`. Селект «Напрям» у дашборді
заповнюється автоматично з бази.


У дашборді та на статичному сайті список **за замовчуванням згрупований за напрямами**,
причому **відходи та освіта йдуть першими** (`src/grant_radar/tracks.py` → `PRIORITY_VIEW`).
Перемикач «групувати за…» дозволяє згрупувати за типом заявника або показати єдиний список.

### 🚛 Бонус за техніку, контейнери й обладнання
Якщо з можливості видно, що за кошти можна **придбати контейнери, сміттєвози, спецтехніку,
транспорт чи обладнання**, запис отримує:
* бали групи `equipment` (20, профіль `config/profile.yaml`);
* додатковий бонус `scoring.equipment_bonus: 10` (×1.0 у заголовку, ×0.6 у тексті);
* бейдж **🚛 техніка / контейнери** і причину «🚛 можливе придбання техніки/контейнерів/обладнання».

Фільтр «лише з технікою» (`?equip=1`) показує тільки такі записи,
фільтр «Напрям» (`?track=waste`, `?track=education`) — конкретний напрям.

### 🎓 Освітній напрям
Окремі джерела й запити: Erasmus+ Україна (`erasmus_ua`), запити SEDIA
(vocational education and training, school education infrastructure, skills development local).
Загальні навчальні слова («capacity building», «тренінг», «digital skills») винесено
в групу `skills` — вони дають бали, але не роблять запис «освітнім»,
щоб напрям «Освіта» лишався чистим.

```yaml
    params:
      item: "div.card"        # або одразу "a[href*='/grant/']"
      title: "h3"             # необов'язково
      summary: "p.excerpt"    # необов'язково
      urls: ["...сторінка 2", "...сторінка 3"]   # необов'язково
      limit: 40
```
* `websearch` — пошук у вебі через DuckDuckGo без ключа (16 українських запитів).
  ⚠️ DuckDuckGo блокує хмарні IP, тому в репозиторії джерело вимкнене
  (`enabled: false`); на домашньому комп'ютері чи іншому раннері вмикається одним рядком.

## 💶 Фільтр і сортування за бюджетом

Агент намагається визначити **орієнтовну суму фінансування на проєкт у євро**
(`src/grant_radar/budget.py`) і розкладає можливості за діапазонами:

| Діапазон | Позначка |
|---|---|
| до 100 000 € | `s` — 💶 до 100 тис. € |
| 100 000 – 500 000 € | `m` — 💶 100–500 тис. € |
| понад 500 000 € | `l` — 💶 понад 500 тис. € |
| суму не вказано | `unknown` |

Звідки береться сума:
* портал **EU Funding & Tenders** — поле `maxContribution` (максимальний внесок ЄС
  на один грант); якщо його немає — річний бюджет теми / очікувану кількість грантів;
* **Світовий банк** — сума проєкту в USD (перераховується в євро);
* решта джерел — розпізнавання сум у тексті: `€250 000`, `EUR 1.5 million`,
  `до 500 тис. євро`, `2 000 000 грн`, `50,000 USD` тощо.
  Гривні/долари/злоті перераховуються за приблизними курсами (`budget.RATES`),
  роки на кшталт «2027 European…» відсікаються.

У дашборді та на статичному сайті з'явилися:
* селект **«будь-який бюджет / до 100 тис. / 100–500 тис. / понад 500 тис. / суму не вказано»**;
* сортування **«за бюджетом ↓»** і **«за бюджетом ↑»** (записи без суми — у кінці);
* бейдж на картці, напр. **💶 9,5 млн €**;
* сума в дайджесті `data/digest.md`.

API: `/api/opportunities?budget=m&order=budget&limit=50`.
Межі діапазонів змінюються константами `SMALL_MAX` / `MID_MAX` у `src/grant_radar/budget.py`.

## 🔗 Першоджерело: де насправді подавати заявку

Каталоги («Час Змін», GetGrant, ГУРТ, «Громадський простір») і новини — це **посередники**.
Заявку подають на сайті донора. Тому після скорингу агент виконує окремий крок:

```bash
python -m grant_radar resolve --min-score 15 -n 600      # знайти першоджерела
python -m grant_radar resolve --all                      # перепровірити вже опрацьовані
python -m grant_radar resolve --search-min 50            # пошук в інтернеті лише для топових
```

Як це працює (`src/grant_radar/resolve.py`):
1. Якщо запис прийшов із **Google News** (посилання веде на SPA-сторінку Google),
   агент відновлює пряме посилання на статтю через новинний пошук Bing RSS.
2. Відкриває сторінку оголошення, викидає меню, футер, бокові панелі й шукає
   в тілі статті зовнішні посилання.
3. Ранжує кандидатів: форма подачі (forms.gle, Google Docs, KoboToolbox, Smartsheet,
   Typeform) **+6**, домен донора (undp.org, europa.eu, diia.gov.ua, …) **+4**,
   текст «подати заявку / аплікаційна форма / детальніше / джерело / ТУТ» **+3**.
   Соцмережі, кнопки «поділитися», сам каталог і пошукові системи відкидаються.
4. **Якщо посилання в тексті немає взагалі** — вмикається ланцюжок фолбеків
   (лише для записів із балом від `--search-min`, за замовчуванням 35):
   - веб-пошук (DuckDuckGo Lite) — приймаються лише домени донорів і сервіси подачі;
   - чужі публікації про цю ж програму (новинний індекс Bing): агент відкриває
     2–4 незалежні статті й шукає донорське посилання в них;
   - довідник `config/donors.yaml` (37 донорів): за згадкою «ПРООН», «EU4Business»,
     «Дія.Бізнес» тощо дає офіційну сторінку конкурсів цього донора.
     Таке посилання позначається як **«сторінка донора»** — кнопка підписана
     🏛 «Сайт донора — шукати конкурс», щоб не плутати з формою заявки.
5. Короткі посилання (`bit.ly`, `cutt.ly`, `tinyurl`…) розгортаються у кінцевий URL.
6. Зберігає `apply_url`, `apply_host`, `apply_label` і, за потреби, `article_url`.

> **Про безкоштовні пошуковики.** Публічні рушії часто блокують серверні IP
> (DuckDuckGo відповідає кодом 202, Mojeek/Qwant/Yep — 403). Тому пошук — лише
> один із трьох фолбеків, і його відмова нічого не ламає: агент просто переходить
> до новинного індексу й довідника донорів. Якщо захочете стабільний пошук —
> додайте безкоштовний ключ Brave Search API у Secrets і розширте `_search_official`.

### Довідник донорів — `config/donors.yaml`

Формат простий, доповнювати можна без коду:

```yaml
donors:
  - name: ПРООН (UNDP Україна)
    url: https://www.undp.org/uk/ukraine/calls-proposals
    match: [проон, "undp"]
```

Збіг у заголовку/описі зараховується завжди, у тілі статті — лише для назв
від 6 символів (щоб «ЄС» чи «МОМ» не ловилися випадково).

**У дашборді й на сайті:** заголовок картки веде одразу на першоджерело,
поряд — бейдж 🔗 з доменом донора, під карткою — зелена кнопка
**«🔗 Подати заявку / першоджерело»** та дрібне посилання **«ℹ️ анонс»** на каталог,
звідки можливість знайдено. Є фільтр **«🔗 є посилання на подачу»** і лічильник

## 🚫 Відсів: у стрічці лише те, на що можна подати заявку

Мета агента — не читати новини про гранти, а подавати заявки. Тому після
скорингу й пошуку першоджерел виконується крок `screen`
(`src/grant_radar/screening.py`), який ховає з ленти три типи записів:

| Причина | Що саме ховаємо | Приклад |
|---|---|---|
| `expired` | дедлайн подачі вже минув | «КОЛИ: до 02.05.2023» |
| `no_source` | новина без знайденого першоджерела — немає куди подавати | «Конкурс грантів…» із Google News, донора знайти не вдалось |
| `news` | новина про вже виданий грант, історія успіху, репортаж | «Громада отримає 1 млн грн», «…: як ветеран розвиває бізнес» |
| `vacancy` | вакансія чи пошук експерта | «Вакансія: Фахівець з технічної підтримки громади» |
| `not_a_call` | стаття без жодних ознак конкурсу чи фінансування | «Чи варто поспішати з новими АЕС: уроки Норвегії» |
| `event` | вебінар, тренінг, форум — заявку на грант там не подаси | «Відбудеться воркшоп програми…» |
| `stale` | оголошення старше за рік, дедлайн не підтверджено (для проєктів МФО — 3 роки) | проєкт МФО 2014 року |
| `tender` | тендер на закупівлю (підряд), а не грант для заявника | «Portugal – Recycling equipment – CPV 42914000» |

**Усі дати зводяться до ISO.** API Світового банку, наприклад, віддає
`closingdate` у вигляді `6/30/2025 12:00:00`. Раніше такий рядок зберігався
«як є», і порівняння з сьогоднішньою датою йшло як порівняння тексту
(«6» > «2»), тож закритий у 2025-му проєкт показувався як чинний. Тепер будь-яка
дата нормалізується (`screening.norm_date`), а нерозпізнана — відкидається.
Додатково ховаються записи з явною позначкою «Статус: Closed».

```bash
python -m grant_radar screen              # швидкий відсів по наявних даних
python -m grant_radar screen --fetch 300  # ще й довантажити 300 сторінок заради дедлайну
python -m grant_radar screen --redate     # перерахувати дедлайни з тексту (чистка хибних дат)
python -m grant_radar check               # самоперевірка: чи не лишилось протермінованого
```

### Самоперевірка `check`

Команда проходить по всій видимій стрічці й падає з кодом 1, якщо знайде:
протерміновану дату, дату в нерозпізнаному форматі або оголошення без дедлайну,
старіше за дозволений строк. У GitHub Actions вона стоїть окремим кроком після
`screen`, тож зламаний запис більше не доїде до сайту непоміченим.

Записи **не видаляються** — їм проставляється `actionable = 0` і `hide_reason`.
Побачити відсіяне можна чекбоксом **«🚫 показати відсіяні»** в дашборді або
параметром `?hidden=1` (і `hidden=true` в `/api/opportunities`).

**Як знаходиться дедлайн.** Спершу беремо дату з джерела (портал ЄС, TED
віддають її структуровано). Якщо її немає — виймаємо з тексту оголошення:
`КОЛИ: до 02.05.2023`, `Заявки приймаються до 15 листопада 2026`,
`Deadline: 30 June 2026`, `Реєстрація до 5 грудня` (рік без вказівки →
найближчий майбутній).

**Дати без року прив'язуються до дати публікації оголошення**, а не до
поточного року: інакше архівний пост «Заявки приймаються з 20 червня по
20 липня 2025» перетворювався на «20 червня 2027», і закритий конкурс
виглядав як відкритий. Якщо в тексті хоч раз написано рік явно — довіряємо
лише таким датам, а в діапазоні «з A по B» дедлайном вважається пізніша дата.
Дату публікації агент бере зі сторінки (`datePublished`, `article:published_time`,
`<time datetime>`), а не лише з RSS.

Дата зараховується **лише поряд зі словами-маркерами подачі** («дедлайн»,
«термін подання», «прийом заявок», «КОЛИ:», `deadline`, `apply by`) і
**відкидається**, якщо поруч стоїть «громадське обговорення», «консультації»,
«звітність», «цілей до 2050 року» тощо. Саме через надто вільний пошук дат
у стрічку колись потрапила новина про АЕС із «дедлайном 08.10.2026», узятим
з абзацу про громадське обговорення, — тепер такі дати не приймаються, а
разова чистка `screen --redate` зняла 152 хибні дати зі старих записів.

### Декодування Google News

Посилання з Google News виглядають як `news.google.com/rss/articles/CBMi...` —
це токен, а не адреса. Агент розкодовує його офіційним шляхом (виклик
`batchexecute` з підписом зі сторінки) і отримує справжній URL статті, а вже
з неї витягує донорське посилання. Саме завдяки цьому кількість знайдених
першоджерел зросла з 74 до **130**, а новин без джерела стало на чверть менше.

**Тендери вимкнено.** Джерело TED (`config/sources.yaml`, `id: ted`) переведено
в `enabled: false`, а правило `tender` ховає будь-які закупівлі, що приходять
з інших стрічок: позначку CPV, «Тендер:», «contract notice», «запит цінових
пропозицій». Виняток — якщо в тексті є слово «грант»/`call for proposals`
(буває, що грантова програма оголошується через тендерну платформу).
Щоб повернути закупівлі, поставте `enabled: true` для `ted` і приберіть
`"ted"` із `TENDER_SOURCES` у `screening.py`.

**Поточний стан бази:** 2091 запис → у стрічці **585**, відсіяно **1506**:
859 протермінованих, 313 статей без ознак конкурсу, 190 тендерів,
54 застарілих оголошення, 53 новини без першоджерела, 31 новина/історія успіху,
4 вакансії, 2 події.

## 🔍 Як розширити пошук і знаходити більше грантів

Чотири важелі — усі безкоштовні, без API-ключів.

### 1. Запити до порталу ЄС (найбільший улов)
`config/sources.yaml` → `eu_ft_portal` → `params.queries`. Кожен рядок — окремий
пошук по Funding & Tenders Portal; `max_pages: 8` × `page_size: 100` сторінок на запит.
Зараз 33 запити (відходи, вода, благоустрій, транспорт, техніка, громади, освіта, бізнес).
Додати свій — просто дописати рядок:
```yaml
        - "biogas plant municipality"
```

### 2. Пошук по новинах — тип джерела `gnews` (Google News RSS)
Знаходить оголошення там, де немає власної RSS: регіональні ЗМІ, сайти громад, донори.
```yaml
  - id: gnews_ua
    type: gnews
    params:
      lang: uk
      country: UA
      per_query: 20
      queries:
        - "грант сміттєвоз OR контейнери OR спецтехніка громада when:180d"
```
Підтримуються оператори Google: `"точна фраза"`, `OR`, `-виключити`,
`site:example.com`, `when:30d/120d/180d`. Саме цей канал дає найкращі «місцеві» знахідки
(наприклад «ДО 72 000 ДОЛ — ГРАНТИ НА РЕМОНТ І ОБЛАДНАННЯ ДЛЯ ОСВІТНІХ ЗАКЛАДІВ»).

### 3. Запити до TED (тендери ЄС)
`ted` → `params.queries`, синтаксис експерт-пошуку TED:
* `notice-title ~ (waste) AND publication-date>=today(-30)` — свіжі оголошення;
* `classification-cpv IN (34144510 44613700)` — сміттєвози й контейнери за кодами CPV;
* `place-of-performance-country-lot=UKR`, `buyer-country=UKR` — що робиться в Україні.

### 4. Нові RSS-джерела
Додати можна будь-яку стрічку:
```yaml
  - id: my_source
    name: "Назва"
    type: rss
    region: UA
    enabled: true
    weight: 1.0
    url: "https://example.org/feed/"
```
Перед додаванням перевірте, що стрічка жива:
`curl -s URL | head` — має бути XML з `<item>`.

### Якщо знахідок усе одно замало
* послабте пороги в `config/profile.yaml` → `scoring.medium_threshold` (зараз 35);
* додайте слова у відповідну групу `keyword_groups` (бал групи = `points`);
* приберіть зайві `negative`-слова, якщо вони ріжуть потрібне;
* підніміть `max_pages` у `eu_ft_portal` (кожна сторінка — +100 тем).

**Що дало розширення цього разу:** 1291 → **1841 запис** (+550), 🔥 високих 22 → **51**,
🚛 з технікою 121 → **216**, із визначеною сумою 468 → **523**, активних джерел 15 → **21**.
